# コラム 01: ライプニッツ vs ニュートン — 記号の優劣が、国の数学を 100 年遅らせた

> *どちらが先に微積分を発見したかの争いは、実は「どちらの記号が使いやすいか」の勝負でした。*

## 二人の天才が、同じものを別々に見つけた

17 世紀後半、ヨーロッパの二人の天才が、ほぼ同時期に微積分にたどり着きました。

| | **アイザック・ニュートン** | **ゴットフリート・ライプニッツ** |
|---|---|---|
| 国 | イングランド | ドイツ（当時は神聖ローマ帝国） |
| 本業 | 物理学者・数学者・錬金術師・造幣局長官 | 哲学者・外交官・法律家・図書館長 |
| 着想 | 1665〜1666 年頃 | 1675 年頃 |
| 発表 | **遅い**（1687年の『プリンキピア』など） | **早い**（1684年に論文発表） |
| 呼び名 | 流率法 (method of fluxions) | 微分法 (calculus differentialis) |

ニュートンのほうが**着想は早かった**とされます。ところが彼は発表をひどく渋りました。
論争を嫌う性格だったとも、錬金術など他の研究に没頭していたとも言われます。

一方ライプニッツは、着想から 10 年足らずで論文にして世に出しました。

そして始まったのが、科学史上もっとも有名な**優先権論争**です。

## 泥沼の論争

イギリス側は「ライプニッツはニュートンの手稿を見て盗んだ」と主張し、
大陸側は「ライプニッツは独立に発見した」と反論しました。

1712 年、**王立協会**が調査委員会を設けて裁定を下します。結論は「ニュートンが先」。

ただしこの裁定には、後世から見て決定的な問題がありました。
**当時の王立協会の会長はニュートン自身**であり、
報告書の実質的な執筆にもニュートンが関与していたと伝えられています。

> 📌 現代の研究倫理から見れば、明らかな利益相反です。
> 現在の科学史研究では「**両者が独立に発見した**」というのが定説になっています。

論争は 1716 年にライプニッツが亡くなるまで続き、後味の悪い結末を迎えました。

## 本当に重要だったのは、記号のほうだった

さて、ここからがこのコラムの本題です。

歴史的に見て決定的だったのは「**どちらが先か**」ではなく、
「**どちらの記号が使いやすかったか**」でした。

### ニュートンの記法 — 点を打つ

ニュートンは、時間で微分することを**文字の上の点**で表しました。

$$
\dot{x} \quad \ddot{x} \quad \dddot{x}
$$

「エックス・ドット」「エックス・ダブルドット」。1 階微分、2 階微分、3 階微分です。

**利点**: 短い。物理では時間微分が圧倒的に多いので、速度 $\dot{x}$、加速度 $\ddot{x}$ と書けて便利。

**欠点**: 「**何で微分したか**」が書けない。時間微分だと暗黙に決め打ちしています。
多変数になった瞬間、点だけでは表現しきれません。

### ライプニッツの記法 — 分数のように書く

ライプニッツは 1675 年、積分記号 $\int$ を初めて使ったとされます。
これはラテン語の **summa（和）の頭文字 s** を縦に引き伸ばした形です。

$$
\int f(x)\, dx \qquad \frac{dy}{dx} \qquad \frac{\partial f}{\partial x}
$$

**利点**: 「**何で微分したか**」が式の中に書いてある。そしてもう一つ、決定的な長所があります。

## ライプニッツ記法の必殺技 — 連鎖律が「約分に見える」

合成関数の微分（連鎖律）を、両方の記法で書いてみましょう。

**ライプニッツ記法**:

$$
\frac{dy}{dx} = \frac{dy}{du} \cdot \frac{du}{dx}
$$

$du$ が**約分されて消えるように見えます**。実際には分数ではないので約分ではないのですが、
**そう見える**おかげで、公式を覚える必要すらありません。

**ニュートン記法**（同じ内容）:

$$
\dot{y} = y'(u) \cdot \dot{u}
$$

... 覚えるしかありません。

> 💡 **「正しい」だけでなく「直感的に見える」記号が勝つ。**
> ライプニッツは記号の設計を意識的に研究していた人物で、
> 「良い記号は思考の労力を減らす」という趣旨のことを書き残しています。
> 彼は普遍的な記号言語（characteristica universalis）を構想した、
> 記号そのものの思想家でもありました。

## そしてイギリスは 100 年遅れた

論争の後、イギリスの数学界は愛国心から**ニュートン記法に固執**しました。
大陸ヨーロッパはライプニッツ記法を採用しました。

結果はどうなったか。

| | 18 世紀の展開 |
|---|---|
| **大陸** | オイラー、ベルヌーイ一族、ラグランジュ、ラプラス — 解析学が爆発的に発展 |
| **イギリス** | ニュートンの威光の下で停滞。目立った解析学の進展が乏しい時期が続く |

使いにくい記号で書き続けたことが、思考のコストを上げ続けたのです。

### 反乱: 「ドット狂いを倒せ」

1812 年、ケンブリッジ大学の学生たちが **解析協会 (Analytical Society)** を結成します。
中心にいたのは、後に**階差機関**の設計で「コンピュータの父」と呼ばれる
**チャールズ・バベッジ**、天文学者ジョン・ハーシェル、数学者ジョージ・ピーコックら。

彼らの目的はただ一つ、**ライプニッツ記法をイギリスに導入すること**でした。

バベッジは後年、この運動をこう洒落たと回想しています（意訳）:

> **「大学の *Dot-age*（ドット狂い / 老いぼれ）に対抗して、
> 純粋な *D-ism*（d 記法主義 / 悪魔崇拝）の原理を掲げる」**

`dotage`（老いぼれ）と `dot`（点記法）、`deism`（理神論）と `d-ism`（$d$ 記法）を
掛けた、なかなか辛辣な言葉遊びです。

この運動は成功し、イギリスの数学は再び国際的な流れに合流しました。

## 現代への接続 — どちらも生き残っている

面白いことに、**両方の記法が今も現役**です。用途で棲み分けました。

| 場面 | 使われる記法 | 例 |
|---|---|---|
| 物理・制御工学（時間微分） | **ニュートン**（ドット） | $\dot{x} = v$, $\ddot{x} = a$ |
| 数学・機械学習（一般の微分） | **ライプニッツ** | $\dfrac{\partial L}{\partial \theta}$ |
| 簡潔に書きたいとき | ラグランジュ（プライム） | $f'(x)$, $f''(x)$ |
| 作用素として扱うとき | オイラー | $D_x f$ |

深層学習の論文で圧倒的に使われるのは**ライプニッツ記法**です。

$$
\frac{\partial \mathcal{L}}{\partial \theta_i}, \qquad
\theta \leftarrow \theta - \eta \frac{\partial \mathcal{L}}{\partial \theta}
$$

理由はやはり、**誤差逆伝播が連鎖律の繰り返し**だからです。

$$
\frac{\partial \mathcal{L}}{\partial w_1}
= \frac{\partial \mathcal{L}}{\partial a_3}
\cdot \frac{\partial a_3}{\partial a_2}
\cdot \frac{\partial a_2}{\partial a_1}
\cdot \frac{\partial a_1}{\partial w_1}
$$

「隣り合う項が約分されて、端だけ残る」という見た目が、
何層あっても計算の流れを追いやすくしてくれます。

**300 年前の記号の選択が、今のニューラルネットワークの論文の読みやすさを支えている**わけです。

### Python ではどう書くか

コードでは記号ではなく**関数**として表現します。

```python
import jax
import jax.numpy as jnp

def f(x: jnp.ndarray) -> jnp.ndarray:
    """f(x) = x^3 + 2x

    Args:
        x: 入力 (スカラー)

    Returns:
        f(x) の値
    """
    return x**3 + 2 * x

# ライプニッツ記法の df/dx にあたるもの
df_dx = jax.grad(f)          # 「微分された関数」が返る
d2f_dx2 = jax.grad(jax.grad(f))   # 2 階微分 (ニュートンなら ẍ)

print(df_dx(2.0))     # → 14.0   (3x² + 2 に x=2 を代入)
print(d2f_dx2(2.0))   # → 12.0   (6x に x=2 を代入)
```

`jax.grad` を重ねがけする書き方は、ニュートンのドットを増やす発想に少し似ています。
一方、多変数で「どの変数で微分するか」を指定するときは、ライプニッツ的な明示性が必要になります:

```python
# 引数 0 番目で微分するか、1 番目で微分するかを明示する
g = lambda x, y: x**2 * y
dg_dx = jax.grad(g, argnums=0)   # ∂g/∂x
dg_dy = jax.grad(g, argnums=1)   # ∂g/∂y

print(dg_dx(3.0, 4.0))   # → 24.0   (2xy に (3,4))
print(dg_dy(3.0, 4.0))   # → 9.0    (x²  に (3,4))
```

`argnums` が、まさに $\partial / \partial x$ の「$x$」の部分を担っています。

## まとめ — 記号は思考のインフラ

このコラムで一番持ち帰ってほしいのは、この一点です。

> **良い記号は、思考のコストを下げる。悪い記号は、国の学問を 100 年遅らせる。**

これは数学に限りません。

- プログラミング言語の文法が読みにくければ、バグが増える
- API の名前が分かりにくければ、誤用が増える
- 変数名が `a`, `b`, `tmp` ばかりなら、半年後の自分が苦しむ

$\hat{\theta}$ や $\bar{x}$ に「なぜこの形なのか」を問う姿勢は、
そのまま**良いコードを書く姿勢**につながっています。
