## 1. ひと言で

> **難しい関数を、足し算と掛け算だけでできた多項式に置き換える技。**

ここで素朴な疑問を持ってほしいところです。

電卓で $\sin(1)$ を押すと $0.8414709848\ldots$ が出ます。
では、**電卓の中の人は何をしているのでしょうか?**

$\sin$ は「三角形の辺の比」として定義されました ([`start_here/03_trigonometry.md`](../start_here/03_trigonometry.md))。
でも CPU にできるのは、結局のところ**足し算・引き算・掛け算・割り算**だけです。三角形を測る機能などありません。

答えがテイラー展開です。CPU は内部でこう計算しています:

$$
\sin(1) \approx 1 - \frac{1^3}{3!} + \frac{1^5}{5!} - \frac{1^7}{7!} + \cdots
$$

足し算と割り算だけ。**これなら CPU にもできる。**

つまりテイラー展開は、抽象的な理論ではなく、**あなたが今使っているコンピュータが実際に動かしている仕組み**です。

## 2. 記号と読み方

テイラー展開の一般形はこう書かれます。記号が多いので 1 つずつ分解します。

$$
f(x) = \sum_{n=0}^{\infty} \frac{f^{(n)}(a)}{n!} (x - a)^n
$$

| 記号 | 読み方 | 意味 | Python |
|---|---|---|---|
| $\sum_{n=0}^{\infty}$ | シグマ、$n$ が $0$ から無限大 | 全部足す | `sum(...)` / `for` ループ |
| $f^{(n)}(a)$ | エフの $n$ 階微分の $a$ での値 | $n$ 回微分した関数に $a$ を代入 | `sp.diff(f, x, n).subs(x, a)` |
| $n!$ | $n$ の階乗 (factorial) | $n \times (n-1) \times \cdots \times 1$ | `math.factorial(n)` |
| $a$ | 展開の中心 (center) | 「この点の近くで」近似する基準点 | 定数 |
| $(x-a)^n$ | — | 中心からの距離の $n$ 乗 | `(x - a) ** n` |

$f^{(n)}$ の**上付きカッコ**に注意してください。$f^2$ (2 乗) とは**まったく別物**です。

| 表記 | 意味 |
|---|---|
| $f^{(2)}(x)$ | 2 階微分 $= f''(x)$ ← カッコあり |
| $f^2(x)$ | $f(x)$ の 2 乗 (文脈によっては合成 $f(f(x))$) ← カッコなし |

> 📖 **特別な名前**: 中心が $a = 0$ の場合を、特に **マクローリン展開 (Maclaurin series)** と呼びます。
> $\exp$, $\sin$, $\cos$ は $0$ を中心にすると式がきれいになるので、ほぼ常にマクローリン展開が使われます。

## 3. 直感 — 「接線」を、もっと欲張る

[`02_derivatives.md`](02_derivatives.md) で、**接線**は関数のその点での一番良い直線近似だと学びました。

テイラー展開は、その素直な続きです。

| 次数 | 何で近似するか | 何を合わせているか |
|---|---|---|
| 0 次 | 定数 (水平線) | **値**だけ合わせる |
| 1 次 | 直線 (接線) | 値 + **傾き** (1 階微分) |
| 2 次 | 放物線 | 値 + 傾き + **曲がり具合** (2 階微分) |
| 3 次 | 3 次曲線 | さらに「曲がり具合の変化」(3 階微分) |
| $\vdots$ | $\vdots$ | $\vdots$ |

つまり、

> **「その点でのあらゆる階数の微分をぜんぶ一致させたら、元の関数に戻るはずだ」**

という欲張りな発想です。そして多くの関数で、これは実際にうまくいきます。

$\sin x$ を $x = 0$ の周りで近似すると、次数を上げるほど本物に貼りついていきます:

$$
\begin{aligned}
\sin x &\approx x && \text{(1 次)} \\
\sin x &\approx x - \frac{x^3}{6} && \text{(3 次)} \\
\sin x &\approx x - \frac{x^3}{6} + \frac{x^5}{120} && \text{(5 次)}
\end{aligned}
$$

> 💡 物理でおなじみの **「$\theta$ が小さいとき $\sin\theta \approx \theta$」** (振り子の等時性など) は、この 1 次近似そのものです。教科書が天下り的に出してくるあの近似の正体は、テイラー展開の一番最初の項でした。

notebook では、この「次数を上げると本物に近づく」様子をスライダーで動かせます。

## 4. 主要な展開 (覚える価値のある 4 つ)

$$
\begin{aligned}
e^x &= \sum_{n=0}^{\infty} \frac{x^n}{n!} = 1 + x + \frac{x^2}{2!} + \frac{x^3}{3!} + \cdots
&& (\text{すべての } x) \\[6pt]
\sin x &= \sum_{n=0}^{\infty} \frac{(-1)^n x^{2n+1}}{(2n+1)!} = x - \frac{x^3}{3!} + \frac{x^5}{5!} - \cdots
&& (\text{すべての } x) \\[6pt]
\cos x &= \sum_{n=0}^{\infty} \frac{(-1)^n x^{2n}}{(2n)!} = 1 - \frac{x^2}{2!} + \frac{x^4}{4!} - \cdots
&& (\text{すべての } x) \\[6pt]
\log x &= \sum_{n=1}^{\infty} \frac{(-1)^{n-1} (x-1)^n}{n} = (x-1) - \frac{(x-1)^2}{2} + \cdots
&& (\textcolor{red}{0 < x \le 2 \text{ のみ}})
\end{aligned}
$$

右端の条件に注目してください。

**$\exp$, $\sin$, $\cos$ はすべての $x$ で成り立つのに、$\log$ だけ範囲が付いています。**

この違いが、このページの一番大事なポイントです。第 6 節で正面から扱います。

## 5. Python で実装する (標準形式)

### 5-1. 素朴な実装 — 定義をそのまま書く

$$
e^x \approx \sum_{i=0}^{n} \frac{x^i}{i!}
$$

```python
import math


def exp_taylor_naive(x: float, n: int = 10) -> float:
    """exp(x) をマクローリン展開の第 n 項まで足して近似する (素朴版).

    定義 sum(x^i / i!) をそのままコードにした版。
    読みやすいが、毎回 x**i と i! を計算し直すので効率が悪い。

    Args:
        x: 入力値 (単位なし、実数)
        n: 何項目まで足すか (n >= 0)

    Returns:
        exp(x) の近似値
    """
    return sum(x**i / math.factorial(i) for i in range(n + 1))
```

これは定義に忠実で読みやすい。でも $i = 30$ のとき $30!$ という巨大な数を計算し、$x^{30}$ も計算して割り算します。**毎回ゼロから作り直している**ので無駄が多い。

### 5-2. 漸化式による実装 — 隣の項から作る

そこで、**前の項から次の項を作る**という書き方をします。

$\exp$ の第 $i$ 項を $t_i = \dfrac{x^i}{i!}$ とすると、隣同士にはこんな関係があります:

$$
t_{i+1} = \frac{x^{i+1}}{(i+1)!} = \frac{x^i}{i!} \cdot \frac{x}{i+1} = t_i \cdot \frac{x}{i+1}
$$

つまり **1 回の掛け算だけ**で次の項が手に入る。階乗も累乗も一切いりません。

```python
def exp_taylor(x: float, n: int = 10) -> float:
    """exp(x) をマクローリン展開の第 n 項まで足して近似する (漸化式版).

    t_{i+1} = t_i * x / (i+1) の関係を使い、各項を前の項から
    掛け算 1 回で作る。階乗も累乗も計算しないので高速かつ安定。

    Args:
        x: 入力値 (単位なし、実数)
        n: 何項目まで足すか (n >= 0)

    Returns:
        exp(x) の近似値
    """
    total = 0.0
    term = 1.0  # t_0 = x^0 / 0! = 1
    for i in range(n + 1):
        total += term
        term *= x / (i + 1)  # 次の項へ更新
    return total
```

$\sin$ と $\cos$ も同じ発想です。ただし 1 つ飛ばしの項なので、更新の比が変わります:

$$
t_{i+2} = t_i \cdot \frac{-x^2}{(i+1)(i+2)}
$$

分子の $-x^2$ が、符号の交代 ($+, -, +, -, \ldots$) と 2 つ飛ばしの累乗を**同時に**引き受けているのが気持ちの良いところです。

```python
def sin_taylor(x: float, n_terms: int = 8) -> float:
    """sin(x) をマクローリン展開で近似する (漸化式版).

    Args:
        x: 角度 (単位: ラジアン)
        n_terms: 実際に足す項数 (次数ではないことに注意)

    Returns:
        sin(x) の近似値
    """
    total = 0.0
    term = x  # 第 1 項は x
    for i in range(n_terms):
        total += term
        # x^(2i+1) -> x^(2i+3) への更新 (符号反転込み)
        term *= -(x**2) / ((2 * i + 2) * (2 * i + 3))
    return total


def cos_taylor(x: float, n_terms: int = 8) -> float:
    """cos(x) をマクローリン展開で近似する (漸化式版).

    Args:
        x: 角度 (単位: ラジアン)
        n_terms: 実際に足す項数

    Returns:
        cos(x) の近似値
    """
    total = 0.0
    term = 1.0  # 第 1 項は 1
    for i in range(n_terms):
        total += term
        term *= -(x**2) / ((2 * i + 1) * (2 * i + 2))
    return total
```

### 5-3. SymPy に答え合わせしてもらう

手で導いた展開が合っているか、記号計算で確かめられます。

```python
import sympy as sp

x = sp.Symbol('x')

# series(関数, 変数, 展開の中心, 何次まで)
print(sp.series(sp.exp(x), x, 0, 6))
# → 1 + x + x**2/2 + x**3/6 + x**4/24 + x**5/120 + O(x**6)

print(sp.series(sp.sin(x), x, 0, 8))
# → x - x**3/6 + x**5/120 - x**7/5040 + O(x**8)

print(sp.series(sp.log(x), x, 1, 4))
# → -1 - (x - 1)**2/2 + (x - 1)**3/3 + x + O((x - 1)**4, (x, 1))
#   (項の並び順は SymPy の内部順序。-1 + x をまとめると (x-1) になる)
```

末尾の $O(x^6)$ は **ランダウの記号 (big-O notation)**、「ラージオー」と読みます。
「ここから先は $x^6$ 以上の項が続くけど省略した」という意味です。$x$ が $0$ に近ければ $x^6$ は極めて小さいので、無視できる誤差、というニュアンスです。

> 📌 アルゴリズムの計算量で見る $O(n^2)$ と**同じ記号**ですが、向きが逆です。計算量では $n \to \infty$ (大きい方) を、テイラー展開では $x \to 0$ (小さい方) を見ています。同じ記号で違う話をするのは数学あるある。[`AGENTS.md`](../AGENTS.md) の「同じ記号でも分野により意味が異なる」の実例です。

## 6. ⚠️ 収束半径 — 「項を増やせば精度が上がる」が破れるとき

ここからがこのページの核心です。

素朴に考えると、**項を増やせば増やすほど答えは正確になる**はずです。実際 $\exp$ ではそうなります。

でも $\log$ で同じことをすると、**信じられないことが起きます**。

### 6-1. 実際に壊してみる

$\log$ の展開 (中心 $a=1$) を、いろんな $x$ で項数を増やしながら計算した結果です:

| $x$ | 真の値 $\log x$ | $n=10$ | $n=30$ | $n=100$ |
|---|---|---|---|---|
| $1.1$ | $0.0953101798$ | $0.0953101798$ | $0.0953101798$ | $0.0953101798$ |
| $1.5$ | $0.4054651081$ | $0.4054346478$ | $0.4054651081$ | $0.4054651081$ |
| $2.0$ | $0.6931471806$ | $0.6456349206$ | $0.6767581377$ | $0.6881721793$ |
| $2.5$ | $0.9162907319$ | $-2.403097098$ | $-3782.65605$ | $-2.43 \times 10^{15}$ |
| $3.0$ | $1.0986122887$ | $-64.82539683$ | $-23592964.64$ | $-8.42 \times 10^{27}$ |

$x = 3$ の行を見てください。真の値は $1.0986\ldots$、つまり **1 くらい**です。

なのに近似値は $-64$、$-2359$ 万、そして $-8.42 \times 10^{27}$。

**項を増やすほど、答えから猛烈な勢いで遠ざかっています。**

これは実装のバグではありません。数学的にそうなるのが正しい。

### 6-2. なぜこうなるのか

$\log$ の展開の第 $n$ 項は $\dfrac{(-1)^{n-1}(x-1)^n}{n}$ です。ここで $(x-1)^n$ の部分に注目します。

| $x$ | $|x-1|$ | $(x-1)^n$ は $n$ が増えると | 結果 |
|---|---|---|---|
| $1.1$ | $0.1$ | $0.1, 0.01, 0.001, \ldots \to 0$ | 項が消えていく → **収束** ✅ |
| $2.0$ | $1.0$ | $1, 1, 1, \ldots$ | 項が $1/n$ でしか減らない → **超低速で収束** 🐢 |
| $3.0$ | $2.0$ | $2, 4, 8, 16, \ldots \to \infty$ | 項が爆発する → **発散** ❌ |

分母の $n$ は 1 次でしか増えないのに、分子の $2^n$ は指数関数的に増えます。**指数関数は多項式に必ず勝つ**ので、項は無限に大きくなり、足し合わせた結果も無限に飛んでいきます。

この境界線 — 「中心からどれだけ離れるまでなら収束するか」の距離を、**収束半径 (radius of convergence)** と呼びます。

$$
\log x \text{ の中心 } a=1 \text{ での収束半径は } R = 1
$$

つまり中心 $1$ から距離 $1$ 以内、$0 < x < 2$ の範囲でしか使えません ($x=2$ はぎりぎり境界で、収束はするものの上の表の通り絶望的に遅い)。

一方 $\exp$, $\sin$, $\cos$ の収束半径は $R = \infty$。だからどんな $x$ でも項を増やせば必ず正確になります。

### 6-3. ここから学ぶべきこと

> **近似式には必ず「有効範囲」がある。範囲外で使うと、間違うだけでなく、努力するほど悪化する。**

これは数学に限った話ではありません。

- 機械学習モデルを訓練データの分布外 (out-of-distribution) で使うと、自信満々に大外しする
- 物理の近似式を適用範囲外で使うと、桁が合わなくなる
- $\sin\theta \approx \theta$ を $\theta = 3$ で使えば当然壊れる ($\sin 3 = 0.141$ に対し近似値 $3$)

**「この式はどこまで信じていいのか」を必ず確認する習慣**は、テイラー展開で最初に身につけるのが一番わかりやすい。

## 7. JAX 形式 — 微分係数を自動で取る

第 2 節の一般形をもう一度見てください。

$$
f(x) = \sum_{n=0}^{\infty} \frac{f^{(n)}(a)}{n!}(x-a)^n
$$

テイラー展開を作るには $f^{(n)}(a)$、つまり**何階でも微分した値**が必要です。手で計算すると大変ですが、`jax.grad` は**微分した関数を返す**ので、重ねがけすれば何階でも取れます。

```python
import jax
import jax.numpy as jnp
import jax.scipy.special
import math
from typing import Callable

# --- 高階微分: grad を n 回重ねる ---
def nth_derivative(f: Callable[[float], float], n: int) -> Callable[[float], float]:
    """関数 f の n 階導関数を返す.

    jax.grad は「微分された関数」を返すので、n 回適用すれば n 階微分になる。

    Args:
        f: 微分対象のスカラー関数
        n: 微分の階数 (n >= 0)

    Returns:
        n 階導関数
    """
    for _ in range(n):
        f = jax.grad(f)
    return f


def taylor_coeffs(f: Callable[[float], float], a: float, n_terms: int) -> list[float]:
    """f の a を中心とするテイラー係数 f^(n)(a) / n! を求める.

    Args:
        f: 対象の関数
        a: 展開の中心
        n_terms: 求める係数の個数

    Returns:
        係数のリスト (長さ n_terms)
    """
    return [
        float(nth_derivative(f, n)(a)) / math.factorial(n)
        for n in range(n_terms)
    ]


# sin を 0 中心で展開した係数 (手計算なし!)
print(taylor_coeffs(jnp.sin, 0.0, 8))
# → [0.0, 1.0, -0.0, -0.16666666666666666, 0.0, 0.008333333333333333,
#     -0.0, -0.0001984126984126984]
#          ↑x の係数 1      ↑x^3 の係数 -1/6      ↑x^5 の係数 1/120
# 偶数番目が 0 なのは sin が奇関数だから (-0.0 と 0.0 の混在は符号付きゼロ)
```

$-1/6$ と $1/120$ が出ています。第 4 節で挙げた $\sin$ の展開式と一致します。
**公式を一切与えていないのに、`jax.grad` を重ねるだけで係数が出てきた**のが、ここでの見どころです。

### `vmap` で一気に評価する

近似曲線を描くには、たくさんの $x$ で近似値を計算します。`vmap` を使うと 1 行です。

```python
@jax.jit
def sin_taylor_jax(x: jnp.ndarray, n_terms: int = 8) -> jnp.ndarray:
    """sin(x) のマクローリン近似 (JAX 版, jit 対応).

    Args:
        x: 角度 (単位: ラジアン), shape: () または (N,)
        n_terms: 足す項数 (静的な値として扱われる)

    Returns:
        sin(x) の近似値, shape は x と同じ
    """
    # 各項の指数 2i+1 と係数 (-1)^i / (2i+1)! を先に用意する
    i = jnp.arange(n_terms)                                    # shape: (n_terms,)
    powers = 2 * i + 1                                          # shape: (n_terms,)
    signs = (-1.0) ** i                                         # shape: (n_terms,)
    factorials = jnp.exp(jax.scipy.special.gammaln(powers + 1.0))  # (2i+1)!
    coeffs = signs / factorials                                 # shape: (n_terms,)
    # x[..., None] で shape (N, 1) にして (n_terms,) とブロードキャスト
    return jnp.sum(coeffs * x[..., None] ** powers, axis=-1)    # shape: (N,)


xs = jnp.linspace(-jnp.pi, jnp.pi, 5)      # shape: (5,)
print(sin_taylor_jax(xs))                   # 5 点いっぺんに評価
print(jnp.sin(xs))                          # 本物と比較
```

> ⚠️ `n_terms` のようにループ回数を決める引数は、`jit` の中では**静的 (static)** でなければなりません。上のコードは `jnp.arange(n_terms)` の形にして配列演算に落とし込むことで、Python の `for` ループを消しています。これは [`07_jax/03_jit_vmap.md`](../07_jax/03_jit_vmap.md) で扱う「jit の中では Python の制御構文を避ける」の実例です。

## 8. 機械学習への接続

### 8-1. 数値安定性 — 桁落ちという実害

第 6 節では「数学的に発散する」例を見ました。今度は、**数学的には正しいのに計算機だと壊れる**例です。

$e^{-20}$ をテイラー展開 ($n=50$) で計算してみます:

| $x$ | テイラー ($n=50$) | 真の値 |
|---|---|---|
| $-1$ | $0.3678794412$ | $0.36787944$ |
| $-10$ | $4.539992967 \times 10^{-5}$ | $4.539993 \times 10^{-5}$ |
| $-20$ | $\textcolor{red}{1.046916976}$ | $2.0611536 \times 10^{-9}$ |
| $-30$ | $\textcolor{red}{878229229.3}$ | $9.357623 \times 10^{-14}$ |

$x=-20$ で答えが $2 \times 10^{-9}$ のはずが $1.05$。**9 桁ずれています。**

原因は $\exp$ の収束半径ではありません ($R = \infty$ なので数学的には正しく収束します)。
犯人は**途中の項が巨大になること**です。$x=-20$ のとき、最大の項は $\dfrac{20^{20}}{20!} \approx 4.3 \times 10^7$ にもなります。

$4 \times 10^7$ ほどの正の項と負の項が打ち消し合って、最終的に $2 \times 10^{-9}$ という答えを作る。ところが `float64` の有効数字は約 16 桁しかないので、$10^7$ 同士の引き算では小数点以下 9 桁目あたりで情報が尽きます。**答えに必要な桁が、計算の途中で消し飛んでいる**のです。

これを **桁落ち (catastrophic cancellation)** と呼びます。

実務での対処は、**式を数学的に等価な別の形に書き換えること**です:

```python
# ❌ 負の x で桁落ちする
exp_taylor(-20, n=50)      # → 1.047 (大間違い)

# ✅ 正の側で計算してから逆数を取る (打ち消し合いが起きない)
1.0 / exp_taylor(20, n=100)   # → 2.061e-09 (正しい)
```

### 8-2. softmax の overflow 対策は同じ発想

この「式を等価変形して安定させる」考え方が、ML で最も有名な形で現れるのが **softmax** です。

$$
\mathrm{softmax}(z_i) = \frac{e^{z_i}}{\sum_j e^{z_j}}
$$

$z_i$ が大きいと $e^{z_i}$ が `inf` に振り切れて `nan` が出ます。そこで最大値を引きます:

$$
\mathrm{softmax}(z_i) = \frac{e^{z_i - \max_j z_j}}{\sum_k e^{z_k - \max_j z_j}}
$$

分子・分母に同じ $e^{-\max z}$ を掛けただけなので**数学的には完全に同じ式**。でも指数の中身が必ず $0$ 以下になるので、`inf` が絶対に出ません。

```python
import numpy as np

def softmax_naive(z: np.ndarray) -> np.ndarray:
    """素朴な softmax (大きな入力で overflow する).

    Args:
        z: ロジット, shape: (N,)

    Returns:
        確率ベクトル, shape: (N,)
    """
    e = np.exp(z)
    return e / e.sum()


def softmax_stable(z: np.ndarray) -> np.ndarray:
    """数値的に安定な softmax (max shift 版).

    Args:
        z: ロジット, shape: (N,)

    Returns:
        確率ベクトル, shape: (N,)
    """
    e = np.exp(z - z.max())  # 指数の中身を必ず 0 以下にする
    return e / e.sum()


z = np.array([1000.0, 1001.0, 1002.0])   # shape: (3,)
print(softmax_naive(z))    # → [nan nan nan]  (overflow)
print(softmax_stable(z))   # → [0.09003057 0.24472847 0.66524096]
```

`jax.nn.softmax` や PyTorch の実装は、当然この安定版になっています。
**ライブラリが黙ってやってくれている親切**の正体が、テイラー展開の桁落ちと同じ話だった、というわけです。

### 8-3. その他の登場場面

| 場面 | どう使われるか |
|---|---|
| **活性化関数の近似** | GELU の高速版は $\tanh$ ベースの近似式。$\tanh$ 自体も内部は多項式近似 |
| **ニュートン法** | 損失関数を 2 次までテイラー展開して、その最小値へ跳ぶ ([`05_optimization/`](../05_optimization/README.md)) |
| **ヘッセ行列** | 多変数版テイラー展開の 2 次の項が $\frac{1}{2}\mathbf{h}^\top H \mathbf{h}$ ([`05_gradient_jacobian.md`](05_gradient_jacobian.md)) |
| **`log1p` / `expm1`** | $\log(1+x)$ と $e^x - 1$ を $x \approx 0$ で精度良く計算する専用関数。中身はテイラー展開 |
| **拡散モデル** | 連続時間の定式化で、微小時間の変化をテイラー展開して離散化する |

> 💡 **`np.log1p` を知っておくと得します**: $\log(1 + 10^{-16})$ を素朴に計算すると、`1 + 1e-16` の時点で `1.0` に丸められて答えが $0$ になります。`np.log1p(1e-16)` なら $10^{-16}$ が正しく返ります。確率の対数を扱う ML コードでは日常的に使われます。

## 9. ハマりポイント

| ハマり | 何が起きるか | 対処 |
|---|---|---|
| **収束半径を無視する** | 項を増やすほど答えが悪化する (第 6 節) | 展開の適用範囲を必ず確認する |
| **「$n$」の意味の取り違え** | `sin_taylor(x, n=10)` の `n` が次数なのか項数なのかループ回数なのかで結果が変わる | docstring に明記する。項数なら `n_terms` と名付ける |
| **桁落ち** | 数学的に正しいのに答えが合わない (第 8-1 節) | 等価な式に変形する。`log1p` / `expm1` / max shift を使う |
| **浮動小数点の最後の 1 桁** | `exp_taylor(1, 30) == math.e` が `False` になる | `==` で比較しない。`math.isclose` や `np.isclose` を使う |
| **中心 $a$ を忘れる** | $\log$ を $0$ 中心で展開しようとする ($\log 0$ は未定義なので不可能) | $\log$ は $x=1$ 中心、または $\log(1+x)$ を $0$ 中心にする |

浮動小数点の件は、実際に手元で起こります:

```python
import math
print(exp_taylor(1, 30))        # 2.7182818284590455
print(math.e)                   # 2.718281828459045   ← 最後の桁が違う
print(exp_taylor(1, 30) == math.e)              # False  ← 罠
print(math.isclose(exp_taylor(1, 30), math.e))  # True   ← 正しい比較
```

差はわずか $4.4 \times 10^{-16}$。数学的には完全に一致していますが、`float64` の最後の 1 ビットが違うだけで `==` は `False` を返します。
**数値計算で `==` を使わない**のは、この章に限らず全編を通じた鉄則です。

## まとめ

| 項目 | 要点 |
|---|---|
| **テイラー展開** | 関数を $\sum \frac{f^{(n)}(a)}{n!}(x-a)^n$ という多項式で表す |
| **マクローリン展開** | 中心が $a = 0$ の特別な場合 |
| **なぜ効くか** | あらゆる階数の微分を一致させれば、元の関数に戻る |
| **実装のコツ** | 階乗を毎回計算せず、$t_{i+1} = t_i \cdot (\text{比})$ の漸化式で回す |
| **収束半径** | $\exp, \sin, \cos$ は $R=\infty$。$\log$ は $R=1$ で範囲外は発散 |
| **桁落ち** | 数学的に正しくても、途中の項が巨大だと有効数字が消える |
| **JAX** | `jax.grad` の重ねがけで高階微分 → 展開係数が自動で出る |
| **ML への接続** | softmax の max shift、`log1p`、ニュートン法、ヘッセ行列 |

そして、一番持ち帰ってほしいこと:

> **近似には必ず有効範囲がある。範囲を確認せずに使うと、努力するほど間違いが大きくなる。**
